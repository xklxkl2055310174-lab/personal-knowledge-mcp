# Agent 编排与子 Agent 委派

Agent 全链路：任务接入 -> 上下文管理 -> 执行编排 -> 结果回写。每一步都应该可观测、可复盘。

编排层只负责规划和调度，真实操作（读文件、查 Git、跑命令）全部交给 MCP 工具执行。

子 Agent 委派把“检索”和“总结”拆开：检索 Agent 只负责找证据，总结 Agent 只能基于证据回答，减少幻觉。

单 Agent 的优点是链路短、延迟低；子 Agent 委派的优点是职责清晰、每个 Agent 的上下文更小、token 成本更可控。

委派不是越多越好：每多一个子 Agent 就多一次上下文传递，适合任务能被清晰拆分且中间结果可校验的场景。

Coding Agent 实践中，提示模板、验收清单和常用 Skill 能让 Claude Code / Cursor 的输出更稳定。
